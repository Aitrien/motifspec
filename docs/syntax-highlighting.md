# Syntax highlighting

Hugo highlights code with [Chroma](https://github.com/alecthomas/chroma). MotifSpec maps Chroma's CSS classes to `color.syntax.*` roles, so one stylesheet covers both themes and every colour is checked for contrast.

## Setup

In `hugo.toml`:

```toml
[markup.highlight]
  noClasses = false   # emit classes, not inline colours
  lineNos = false     # opt in per block with {linenos=table}
  codeFences = true
  guessSyntax = false
```

Load `dist/chroma.css` (also bundled in `dist/codex.css`). Do not generate a Chroma theme with `hugo gen chromastyles`; it would hard-code colours and bypass the tokens.

Wrap highlighted output in the code-block component (see `components/code-block.md`) so it gets the header bar, border and copy button.

## Rules

- Every role has a contrast pair against `color.surface.sunken` and `color.syntax.line-highlight` at 4.5:1 or more, in both themes.
- Comments stay upright. No mono italic is loaded, and synthetic italic in code is hard to read.
- Keywords and headings are the only bold roles. Weight is a second cue so highlighting never depends on hue alone.
- Plain identifiers use `color.syntax.variable`, which matches body text, so most code reads as text and the colour goes to structure.
- Diff lines keep their `+` and `-` prefixes; colour is a second signal, never the only one.
